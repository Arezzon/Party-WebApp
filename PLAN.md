# «Тусовка» — план реалізації

Стек: **Astro 7 (SSR, @astrojs/node standalone) + React 19 + Tailwind 4 + shadcn/ui + React Bits (MCP registry)**.
Проєкт: `/data/workspace/tusivka-app`. Node проєкту: 22.23.4 (Astro 7 вимагає ≥22.23.4).

## Що вже зроблено (інфраструктура)
- [x] Astro 7.4.13, SSR-адаптер `@astrojs/node` (режим standalone)
- [x] React 19 + `@astrojs/react`, TypeScript strict, аліас `@/*`
- [x] Tailwind 4 + shadcn/ui (`components.json`, preset nova, `@/` аліас)
- [x] MCP `shadcn` підключено до Hermes (7 інструментів, registry `@reactbits` додано: `https://reactbits.dev/r/{name}.json`)
- [x] Тестовий компонент React Bits `AnimatedContent-TS-TW` встановлено — `npm i` з reg 200, `astro check` 0 errors, `astro build` успішний
- [x] Пам'ять/диск перевірено: ~5.7 GB доступно RAM, 7 GB на диску

## Архітектура (по ТЗ)
- **DB**: SQLite (better-sqlite3), WAL. Сесії — Astro filesystem sessions або БД. Обкладинки — BLOB у SQLite (як у еталоні: перекодування у WebP, `nosniff`, без файлів на диску).
- **Auth**:Better Auth або власний scrypt salt:hash + cookie (HttpOnly, SameSite=Lax, Secure у проді). Обов'язково: перевірка Origin (CSRF), rate-limit логіну (429 після 10 спроб), інвалідація сесії при виході.
- **HTML-екранування** коментарів, UUID id подій, 32-байтові invite-токени.
- **Часи**: зберігати UTC, показувати Kyiv (`Europe/Kyiv`), підставляти у форми редагування коректно (зима/літо).

## Функціонал (7 пунктів ТЗ)
1. Акаунти: реєстрація / вхід / вихід (email + пароль).
2. Створення події: назва, опис, дата+час, кількість місць, обкладинка, публічна/приватна.
3. Головна: список майбутніх публічних подій + пошук за назвою (кирилиця, регістронезалежно, `%` не ламає).
4. Сторінка події: «Іду» / «Скасувати», лічильник вільних місць, коментарі.
5. Автор: редагування/видалення своєї події, список учасників.
6. Приватні події: доступ тільки за посиланням-запрошенням (404 для аноніма й без інвайту скрізь: сторінка, обкладинка, запис, коментар, пошук).
7. Профіль: створені події + події, на які записався.

## Обов'язкові виправлення (6 знахідок, −19 балів)
1. **−5** Політика конфіденційності: окрема сторінка + посилання біля кнопки реєстрації (ст. 12 Закону №2297-VI).
2. **−5** Профіль: редагування імені + видалення акаунта (справді видаляє сесії, події/записи; коментарі знеособлюються; ст. 8).
3. **−5** Server-side обмеження дати події зверху (напр. ≤2 роки) + `max` на інпуті форми (не 9999).
4. **−2** Правила сервісу, кнопка скарги, автор події/коментаря може видаляти коментарі.
5. **−2** Idempotency key на сервері для створення події/коментаря (захист від повторного POST; дублікати за останні секунди від того ж автора).
6. **−2** Header на 375px: `white-space: nowrap`, іконки замість підписів або мобільне меню.

## Додатково з еталону (що вже працює — зберегти)
