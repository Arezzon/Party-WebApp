# Feature Specification: Деплой і надійність «Тусовки»

**Feature Branch**: `003-cloudflare-workers-cicd`
**Created**: 2026-11-25
**Status**: Implemented
**Input**: User description: "Зроби порядок у репозиторії, додай CI/CD через GitHub Actions, підключи Dependabot; сайт має бути швидким і доступним за зручним безкоштовним URL."

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Стабільний публічний URL (Priority: P1)

Відвідувач відкриває сайт за коротким безкоштовним посиланням без імені особистого акаунта в адресі. Посилання працює з валідним HTTPS-сертифікатом і веде до тієї самої версії сервісу після кожного деплою.

**Why this priority**: Без доступного URL усі інші сценарії не мають сенсу.
**Independent Test**: Відкрити `https://tusivka.byndevav.workers.dev/`, перевірити 200, валідний TLS і відсутність особистого логіна в host.
**Acceptance Scenarios**:
1. **Given** задеплоєний сервіс, **When** відвідувач відкриває публічний URL, **Then** відповідь 200 і сторінка відображається без попереджень TLS.
2. **Given** змінено акаунт-субдомен, **When** сертифікат ще не видано, **Then** деплой не оголошується готовим, поки новий hostname не відповідає 200.
3. **Given** старий URL, **When** відвідувач переходить на нього, **Then** він більше не обслуговується.

---

### User Story 2 — Швидке відкриття подій і обкладинок (Priority: P1)

Відвідувач бачить головну майже миттєво, а сторінку події та її обкладинку — без помітної затримки. Повторне відкриття тієї самої обкладинки не витрачає час на повторну передачу.

**Why this priority**: Повільні сторінки подій і зображень псують основний сценарій вибору події.
**Independent Test**: Прогнати `bash scripts/perf-check.sh` на продакшені й portи виміряти час відповіді трьох маршрутів.
**Acceptance Scenarios**:
1. **Given** прогрітий або холодний edge, **When** запитується головна, **Then** час < 400 мс.
2. **Given** публічна подія, **When** відкривається її сторінка, **Then** час < 800 мс.
3. **Given** публічна обкладинка, **When** запитується вперше й повторно, **Then** холодний запит < 500 мс, а повторний обслуговується з кешу без повторного читання BLOB.
4. **Given** приватна подія, **When** запитується її обкладинка, **Then** відповідь не кешується публічно.

### User Story 3 — Автоматична перевірка та деплой (Priority: P1)

Розробник відкриває PR і бачить автоматичні перевірки тестів, типів і білду. Після merge у головну гілку зміни автоматично потрапляють на прод разом із міграціями схеми.

**Why this priority**: Ручні деплої й неперевірені PR легко ламають прод.
**Independent Test**: Відкрити PR, дочекатися зелених перевірок, змержити, перевірити успішний deploy run і доступність сайту.
**Acceptance Scenarios**:
1. **Given** новий PR, **When** запускається CI, **Then** виконуються `npm ci`, `npm test`, `npx astro check`, `npm run build`.
2. **Given** PR із падаючими тестами, **When** CI завершується, **Then** статус black/fail і merge заблокований.
3. **Given** merge у `main`, **When** запускається deploy workflow, **Then** застосовуються D1-міграції й деплоїться Worker.
4. **Given** відсутній секрет Cloudflare, **When** deploy запускається, **Then** він падає з зрозумілою помилкою й не змінює прод.

---

### User Story 4 — Автоматичні оновлення залежностей (Priority: P2)

Команда отримує щотижневі PR на оновлення npm-пакетів і GitHub Actions без ручного моніторингу версій.

**Why this priority**: Залежності швидко старіють, а ручне їх оновлення легко забути.
**Independent Test**: Перевірити наявність `.github/dependabot.yml` і побачити створені Dependabot PR для npm та github-actions.
**Acceptance Scenarios**:
1. **Given** активний Dependabot, **When** настає понеділок, **Then** створюються або оновлюються PR для npm і GitHub Actions.
2. **Given** кілька minor/patch оновлень npm, **When** Dependabot формує PR, **Then** вони згруповані в один PR.
3. **Given** Dependabot PR, **When** запускається CI, **Then** він проходить ті самі перевірки, що й звичайний PR.

---

### Edge Cases

- Новий `*.workers.dev` субдомен може кілька хвилин не мати TLS-сертифіката; готовність оголошується тільки після успішного HTTPS-запиту.
- PAT без `workflow` scope не може пушити `.github/workflows/*.yml`; перед доданням Actions потрібні відповідні права.
- Хоча б однаdependabot-перевірка може бути pending; статус PR не вважається зеленим, поки всі check-и не завершились.
- Edge-кеш може віддавати стару відповідь під час замірів; для bench-ів використовується cache-buster.
- Чистий checkout не має gitignore-ної папки `data/`; Node-фолбек для тестів має створити її самостійно.
- Приватні обкладинки не повинні потрапляти до спільного edge-кешу.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Сервіс МУСТІТЬ бути доступним за публічним HTTPS-URL без імені особистого акаунта.
- **FR-002**: Сервіс МУСТІТЬ зберігати дані у керованій хмарній базі з версійованими міграціями.
- **FR-003**: Публічні обкладинки МУСТІТЬ віддаватися з ETag і кешуватися; приватні — з `no-store`.
- **FR-004**: Незалежні читання сторінки події МУСТІТЬ виконуватися паралельно.
- **FR-005**: CI МУСТІТЬ перевіряти тести, типи та білд на кожному PR і push у головні гілки.
- **FR-006**: Deploy МУСТІТЬ запускатися на push у `main` і вручну через `workflow_dispatch`.
- **FR-007**: Deploy МУСТІТЬ застосовувати міграції бази перед оновленням застосунку.
- **FR-008**: Секрети деплою МУСТІТЬ зберігатися в налаштуваннях репозиторію, а не в коді.
- **FR-009**: Dependabot МУСТІТЬ щотижня перевіряти npm-залежності та GitHub Actions.
- **FR-010**: Репозиторій МУСТІТЬ мати PR-шаблон і сучасний `.gitignore` без дублікатів.

### Key Entities *(include if feature involves data)*

- **Deployment**: публічний hostname, версія застосунку, статус застосованих міграцій.
- **CI Run**: гілка/PR, набір перевірок, підсумковий статус.
- **Dependency Update**: джерело (npm або GitHub Actions), періодичність, згруповані оновлення.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Публічний URL відповідає 200 з валідним TLS у 100% перевірок після деплою.
- **SC-002**: Головна < 400 мс, сторінка події < 800 мс, холодна обкладинка < 500 мс, тепла — з кешу.
- **SC-003**: CI на PR і `main`: 32/32 тестів, 0 помилок типу, успішний білд.
- **SC-004**: Після merge у `main` deploy завершується успішно й сайт проходить smoke-перевірку.
- **SC-005**: Dependabot створює PR для npm і GitHub Actions за розкладом; у репозиторії немає прострочених гілок.
- **SC-006**: Усі секрети зберігаються поза кодом і не потрапляють у git.

## Assumptions

- Безкоштовні плани Cloudflare Workers, D1 і GitHub Actions достатні для демо-навантаження.
- Відвідувачі мають стабільний інтернет і сучасний браузер.
- Чинна модель авторизації, приватності та модерації не змінюється.
- deploys відбуваються тільки з `main` або вручну уповноваженим розробником.
